selfstore.yml

Publish apps from a git repo

A selfstore.yml at the root of a public git repo tells SelfStore which apps the repo publishes. Anyone running SelfStore can add the repo by its URL, and every app in it shows up in their library and on their iPhone.

Each app is one of two kinds:

  • A prebuilt .ipa committed to the repo. SelfStore imports it and re-signs it for the user's devices. Nothing is built.
  • An Xcode project and scheme. SelfStore builds it on the user's Mac, then signs and publishes it.

A repo can mix both, list any number of apps, and publish from several branches.

selfstore.yml
version: 1
branches: [main]

apps:
  - name: Notes
    ipa: selfstore/Notes.ipa

  - name: Widgets
    project: Widgets/Widgets.xcodeproj
    scheme: Widgets

Fields

Top level

  • appslistrequired

    The apps this repo publishes. At least one.

  • branchesstring or list

    Branches to publish every app from, unless the app lists its own. Glob patterns such as release/* work. Defaults to the repo's default branch.

  • versioninteger

    The format version. Currently 1. Optional.

Each app

  • ipapath

    A prebuilt .ipa, relative to the repo root. Use either ipa or project, not both.

  • projectpath

    An .xcodeproj or .xcworkspace, relative to the repo root.

  • schemestring

    The scheme to build. Required with project.

  • schemeslist

    Several schemes from the same project. Each becomes its own app, named after its scheme.

  • namestring

    A label unique within the file. Defaults to the .ipa's file name or the scheme.

  • configurationstring

    The build configuration. Defaults to Release.

  • platformios | macos

    What the scheme builds. Detected when omitted.

  • branchesstring or list

    Overrides the top-level branches for this app.

  • notesstring

    Shown with every version of this app, after the branch and commit.

Paths must stay inside the repo: absolute paths and .. are rejected.

Every field
version: 1
branches: [main, "release/*"]

apps:
  # A prebuilt build in the repo
  - name: Notes
    ipa: selfstore/Notes.ipa
    notes: Built by CI

  # A project SelfStore builds
  - name: Widgets
    project: Widgets/Widgets.xcworkspace
    scheme: Widgets
    configuration: Release
    platform: ios
    branches: [main, beta]

  # Two apps from one project
  - project: Suite/Suite.xcodeproj
    schemes: [Suite, SuiteMac]

Prebuilt .ipa files

Commit the .ipa and point an ipa entry at it. On every pull SelfStore compares the file with the last one it imported, and imports it again only when it changed. The newest five versions are kept.

The .ipa can be signed any way you like: development, ad hoc, or not at all. SelfStore re-signs it with the user's own certificate for their registered devices and keeps the entitlements their App ID allows.

Bundle IDs are rewritten to the user's prefix (Settings ▸ Bundle IDs). With a prefix of com.you, com.acme.Notes installs as com.you.Notes, and its extensions, app groups and iCloud containers move with it. This applies to ipa entries only; projects SelfStore builds keep their own bundle ID.

Large files: .ipa files tracked with Git LFS work when git-lfs is installed on the Mac.
selfstore.yml
apps:
  - name: Notes
    ipa: selfstore/Notes.ipa
  - name: Notes Widget Lab
    ipa: builds/WidgetLab.ipa
    branches: [experiments]
Repo layout
.
├── selfstore.yml
├── selfstore/
│   └── Notes.ipa
└── builds/
    └── WidgetLab.ipa

Xcode projects

A project entry is built on the Mac of whoever added the repo. SelfStore builds without code signing, carries each target's entitlements over, signs the result for the user's devices and publishes it like an upload. Build numbers default to a UTC timestamp.

Projects build when someone chooses Pull & Build (on the Mac, in the menu bar, or on the iPhone), or taps Build on the app. Pull & Build only rebuilds apps whose branch has new commits.

Schemes that build a Mac app produce a .dmg and .zip, notarized when the Mac has a Developer ID certificate.

Building runs the repo's code. Build phases and package plugins execute on the Mac. SelfStore runs git with hooks turned off, but only add repos you trust.
selfstore.yml
apps:
  - name: Trailhead
    project: apps/Trailhead/Trailhead.xcodeproj
    scheme: Trailhead

  - name: Trailhead for Mac
    project: apps/Trailhead/Trailhead.xcodeproj
    scheme: TrailheadMac
    platform: macos

Branches

Every app is published from each branch it matches. Branches come from the app's own branches, then the top-level branches, then the repo's default branch.

Apps from branches other than the default get the branch name appended to their bundle ID, so they install next to the default branch instead of replacing it. Characters that aren't allowed in a bundle ID become hyphens.

SelfStore reads selfstore.yml from each branch, so a branch can add or remove apps. A branch without the file uses the default branch's.

selfstore.yml
branches: [main, beta, "release/*"]
apps:
  - name: Trailhead
    project: Trailhead.xcodeproj
    scheme: Trailhead
Installed bundle IDs
main           com.you.Trailhead
beta           com.you.Trailhead.beta
release/2.0    com.you.Trailhead.release-2-0

Exporting builds

If SelfStore already builds one of your projects, it can write the file for you. Open the project in the App Library and turn on Export the .ipa to the repo after each build.

After every iOS build SelfStore copies the .ipa to selfstore/<Scheme>.ipa in the project's git repo and adds a matching entry to selfstore.yml, keeping anything else in the file. Nothing is committed or pushed: commit both when you want to publish.

Over the API, send PATCH /api/projects/<id> with {"exportToRepo": true}.

selfstore.yml (written by SelfStore)
# SelfStore: apps this repo publishes. Format:
# https://syousif94.github.io/SelfStore/docs.html#selfstore-yml
version: 1
apps:
  - name: Trailhead
    ipa: selfstore/Trailhead.ipa
Terminal
git add selfstore.yml selfstore/
git commit -m "Publish Trailhead 1.4"
git push

Adding a repo

Paste the repo's URL into Add Git Repo from the + menu in the App Library on the Mac, or in the SelfStore iPhone app. owner/repo works as shorthand for GitHub. The repo must be public and served over HTTPS.

SelfStore clones it, reads selfstore.yml, and checks out each published branch. Pull to pick up new commits; Pull & Build also builds projects that changed.

From a script, use the repos API.

Request
curl localhost:8765/api/repos \
  -d '{"url": "acme/field-kit", "build": true}'

HTTP API

The SelfStore API

Everything the apps do goes through a small HTTP API that SelfStore serves on the Mac. Build scripts and coding agents can use it to upload builds, start project builds and read the library.

FromBase URL
The Mac itselfhttp://localhost:8765
Your tailnethttps://<mac>.<tailnet>.ts.net:8767

Request and response bodies are JSON unless noted. Dates are ISO 8601. GET /api/docs returns this reference as Markdown for agents, and SelfStore ▸ Settings ▸ Copy Agent Instructions copies it.

Request
curl localhost:8765/api/info
Response
{
  "service": "SelfStore",
  "apiVersion": 1,
  "name": "Studio Mac",
  "lanURL": "http://studio-mac.local:8765",
  "tailscaleURL": "https://studio-mac.example.ts.net:8767",
  "installsAvailable": true,
  "appCount": 3,
  "signingEnabled": true,
  "bundlePrefix": "com.you"
}

Authentication

Requests from the Mac itself (localhost) need no token.

Devices on your tailnet can, without a token, read the library and do what the iPhone app does: upload .ipa files, add and pull repos, start and cancel builds, and send builds to TestFlight.

Everything else from another machine (deleting, editing notes, adding projects, signing changes) needs the API token from SelfStore ▸ Settings, as a bearer token or a token query parameter.

Keep the token private. It allows changing the library from anywhere that can reach the Mac.
Request
curl -X DELETE \
  -H "Authorization: Bearer $SELFSTORE_TOKEN" \
  https://studio-mac.example.ts.net:8767/api/apps/com.you.Notes/1.2-40

Errors

Errors return a JSON body with a readable message and a conventional status code.

StatusMeaning
400The request is missing something, or a value is invalid.
401The route needs the API token.
404No such app, version, project or repo.
409Conflicts with the current state, such as a version that already exists with replace=false.
422The file or project couldn't be processed: not a valid .ipa, a signing failure, a build error.
500, 502Something failed on the Mac or at App Store Connect.
Response · 422
{
  "error": "Not a valid .ipa: no Payload/*.app/Info.plist"
}

Upload a build

POST/api/apps

Send the .ipa as the raw request body, or as the ipa field of a multipart/form-data form. SelfStore reads the bundle ID, name, version, build and icon from it, re-signs it when signing is set up, and adds it as a new version. Every version is kept until you prune it.

Query parameters

  • notesstring

    Release notes shown on the iPhone. Also accepted as a form field.

  • replaceboolean

    Defaults to true. With false, uploading a version and build that already exist fails with 409.

  • keepinteger

    After uploading, keep only the newest n versions of the app.

  • resignboolean

    Overrides the Mac's re-signing setting for this upload.

  • renameboolean

    Overrides moving the app to the Mac's bundle ID prefix.

Returns

201 with the new version. Its installURL is an itms-services:// link that installs the build on a registered device.

Request
curl --fail-with-body \
  --data-binary @build/Trailhead.ipa \
  "localhost:8765/api/apps?notes=Offline%20maps&keep=10"
Response · 201
{
  "id": "1.4-88",
  "bundleId": "com.you.Trailhead",
  "originalBundleId": "com.acme.Trailhead",
  "name": "Trailhead",
  "version": "1.4",
  "build": "88",
  "uploadedAt": "2026-11-21T18:02:11Z",
  "size": 918442,
  "notes": "Offline maps",
  "source": "Upload",
  "expiresAt": "2027-11-21T18:02:09Z",
  "provisionedDevices": 3,
  "iconPath": "/apps/com.you.Trailhead/1.4-88/icon.png",

Apps and versions

An app is identified by its bundle ID, and holds its versions newest first. A version's id is <version>-<build>, for example 1.4-88. Anywhere a version id is expected, latest works too.

The version object

  • idstring

    <CFBundleShortVersionString>-<CFBundleVersion>.

  • bundleIdstring

    The ID it installs as. originalBundleId is set when SelfStore moved it to the prefix.

  • version, buildstring

    From the app's Info.plist.

  • notesstring

    Release notes, if any.

  • sourcestring

    Where it came from: Upload, a project build, or owner/repo branch @ commit.

  • expiresAtdate

    When its provisioning profile expires.

  • installURLstring

    An itms-services:// link, present when the Mac is shared over Tailscale.

  • testFlightobject

    The latest TestFlight upload, if any.

Endpoints
  • GET/api/apps
  • GET/api/apps/:bundleId
  • GET/api/apps/:bundleId/:version
  • PATCH/api/apps/:bundleId/:version
  • DELETE/api/apps/:bundleId/:version
  • DELETE/api/apps/:bundleId
  • POST/api/apps/:bundleId/prune?keep=3
  • POST/api/apps/:bundleId/:version/resign
Edit release notes
curl -X PATCH localhost:8765/api/apps/com.you.Trailhead/latest \
  -d '{"notes": "Offline maps and a new compass"}'
Keep the newest three
curl -X POST "localhost:8765/api/apps/com.you.Trailhead/prune?keep=3"

Projects

Register an Xcode project once and build it on demand. A build archives without signing, signs for registered devices and publishes the result as a new version of its app. Mac schemes produce a .dmg and .zip instead.

Add a project

POST/api/projects
  • pathstringrequired

    Absolute path to an .xcodeproj or .xcworkspace on the Mac.

  • schemestring

    Defaults to the scheme named after the project, then one with “iOS” in its name, then the first.

  • platformios | macos

    Detected when omitted.

  • buildboolean

    Start a build right away.

Build state

state is queued, building, signing, succeeded, failed or cancelled, with a human-readable step, and error and logTail on failure. Mac builds add artifacts and notarized.

Settings

  • exportToRepoboolean

    Write each build into the project's repo. See Exporting builds.

  • autoBuildNumberboolean

    Stamp builds with a UTC timestamp build number. On by default.

Endpoints
  • POST/api/projects
  • GET/api/projects
  • GET/api/projects/:id
  • PATCH/api/projects/:id
  • POST/api/projects/:id/build
  • POST/api/projects/:id/cancel
  • GET/api/projects/:id/log
  • GET/api/projects/:id/files/:name
  • DELETE/api/projects/:id
Request
curl localhost:8765/api/projects -d '{
  "path": "/Users/me/Trailhead/Trailhead.xcodeproj",
  "scheme": "Trailhead",
  "build": true
}'
Response · 201
{
  "id": "trailhead-trailhead",
  "name": "Trailhead",
  "fileName": "Trailhead.xcodeproj",
  "platform": "ios",
  "state": "queued",
  "step": "Waiting…",
  "signingReady": true
}

Repos

Git repos with a selfstore.yml. Each app the file lists becomes a target: prebuilt .ipa files are imported, and projects appear in /api/projects with repoId, branch and commit.

Add a repo

POST/api/repos
  • urlstringrequired

    An HTTPS git URL, or owner/repo for GitHub.

  • buildboolean

    Build its projects after the first pull.

Pull

POST/api/repos/:id/pull
  • buildchanged | all

    After pulling, build projects with new commits (changed) or every project (all). Omit to only pull.

The repo's state is idle, pulling or failed. Poll GET /api/repos/:id for step, branches and each target's error.

Endpoints
  • POST/api/repos
  • GET/api/repos
  • GET/api/repos/:id
  • POST/api/repos/:id/pull
  • POST/api/repos/:id/build
  • DELETE/api/repos/:id

Signing and devices

With an App Store Connect API key, SelfStore keeps an Apple Distribution certificate and an ad hoc profile containing every registered device, and re-signs each new build with them. Bundle IDs it hasn't seen are registered on the account automatically.

iPhones register themselves by opening /register on the Mac's Tailscale address in Safari. Registering a new device re-signs the latest version of every app so it includes the device.

GET /api/signing reports ready, the certificate, and the registered devices. Entitlements a build asked for but its App ID doesn't allow are listed in the version's signingWarnings.

Endpoints
  • GET/api/signing
  • POST/api/signing/refresh
  • GET/api/devices
  • POST/api/devices
  • POST/api/resign-all
Register a device by UDID
curl localhost:8765/api/devices \
  -d '{"udid": "00008140-001A2B3C4D5E", "name": "Test iPad"}'

TestFlight

POST/api/apps/:bundleId/:version/testflight

Re-signs a stored build for the App Store and uploads it to App Store Connect with the same API key. Returns 202; poll the version for progress.

The version's testFlight.state moves through queued, signing and uploading to succeeded or failed.

  • The app must already exist in App Store Connect.
  • Each upload needs a version and build number App Store Connect hasn't seen. Project builds use timestamps, so they always qualify.
  • Apple processes the build for a few minutes after succeeded.
Request
curl -X POST localhost:8765/api/apps/com.you.Trailhead/latest/testflight
Response · 202
{
  "id": "1.4-88",
  "testFlight": {
    "state": "queued",
    "step": "Waiting…",
    "startedAt": "2026-11-21T18:10:04Z"
  }
}
